# MindLog App

MindLog is a personal journaling and mood tracking application built with React
Native and Expo.

## Завдання 1: Основи React Native та Стилізація (Assignment 3)

Це завдання присвячене створенню базових компонентів інтерфейсу на основі
дизайну у Figma та їх стилізації в React Native.

### 1. Аналіз дизайну

- Проведено аналіз дизайн-макета у Figma.
- Виділено ключові компоненти, що є основою інтерфейсу застосунку MindLog:
  кнопки, картки записів, заголовки, поля вводу та контейнери екранів.

### 2. Створення компонентів у React Native

Для реалізації інтерфейсу було розроблено наступні модульні компоненти:

- **Button (`Button.js`)**: Кастомна кнопка з підтримкою іконок та різних
  варіантів стилізації (primary, secondary, outline, ghost). Використовує
  `TouchableOpacity` для взаємодії.
- **Card (`Card.js`)**: Базовий контейнер для відображення записів та елементів
  списків.
- **AppHeader (`AppHeader.js`)**: Шапка застосунку з підтримкою заголовка,
  підзаголовка та додаткових елементів.
- **InputField (`InputField.js`)**: Стилізоване поле вводу для текстових даних.
- **Typography (`Typography.js`)**: Набір компонентів для відображення тексту
  різних рівнів (`Heading`, `Subheading`, `Body`, `Caption`).
- **ScreenContainer (`ScreenContainer.js`)**: Універсальний компонент для
  обгортки екранів, що забезпечує коректне відображення в межах `SafeAreaView`,
  підтримку прокрутки (`ScrollView`) та обробку клавіатури
  (`KeyboardAvoidingView`).

### 3. Стилізація та Адаптивність

- **Flexbox**: Всі компоненти побудовані з використанням Flexbox для
  забезпечення адаптивності та гнучкості макета (`flexDirection`,
  `justifyContent`, `alignItems`).
- **Адаптація під платформи**: Використовується `Platform.OS` (у
  `ScreenContainer.js`) для специфічної поведінки `KeyboardAvoidingView` на iOS
  та Android.
- **Теми та кольори**: Реалізовано систему тем через `ThemeContext`. Замість
  «магічних чисел» використовуються константи кольорів, що дозволяє легко
  змінювати палітру (підтримка Dark Mode).

### 4. Додаткові вимоги

- **Модульність**: Кожен компонент винесено в окремий файл у папці
  `src/components`.
- **Пропси**: Всі компоненти використовують пропси для передачі динамічних даних
  (`title`, `onPress`, `children`, `variant` тощо).
- **Чистота коду**: Код структурований, компоненти мемоізовані (`React.memo`)
  для оптимізації, використовуються зрозумілі назви змінних та коментарі до
  логіки.

## Завдання 2: Навігація в React Native (Assignment 4)

Це завдання присвячене проєктуванню та реалізації складної структури навігації,
включаючи Stack, Tab та Drawer навігацію.

### 1. Проєктування навігаційної структури

- **Stack Navigation**: Використовується для лінійних переходів, таких як
  авторизація (`SignIn`), початкове налаштування (`Setup`) та перехід до деталей
  запису (`EntryDetail`).
- **Tab Navigation**: Основний інтерфейс застосунку після входу, що забезпечує
  швидкий доступ до Головної, Календаря, Статистики (Insights) та Профілю.
- **Drawer Navigation**: Бокове меню для доступу до налаштувань, підтримки та
  інших допоміжних екранів.

### 2. Реалізація навігації

Навігація реалізована за допомогою бібліотеки `@react-navigation`:

- **`RootNavigator.js`**: Головний стек (`createNativeStackNavigator`), що керує
  переходами між екранами аутентифікації та основним контентом.
- **`TabNavigator.js`**: Реалізує нижню панель вкладок
  (`createBottomTabNavigator`) з кастомними іконками та анімаціями
  (використовується `react-native-reanimated`).
- **`DrawerNavigator.js`**: Реалізує бокове меню (`createDrawerNavigator`), що
  обгортає основну навігацію та додає допоміжні розділи.

### 3. Передача даних між екранами

- Реалізовано передачу параметрів через `navigation.navigate()`. Наприклад, при
  переході до `EntryDetailScreen` передається ID запису.
- На екрані деталей дані отримуються через `route.params`, що дозволяє
  відображати динамічний контент залежно від вибраного елемента.

### 4. Стилізація та Адаптивність

- **Кастомні заголовки**: Використання `screenOptions` для налаштування вигляду
  заголовків, приховування стандартних хедерів та використання кастомного
  компонента `AppHeader`.
- **Іконки та Анімації**: Вкладки мають анімовані іконки (Lucide React Native +
  Reanimated) для покращення UX.
- **Адаптивність**: Навігація протестована на iOS та Android, враховані
  особливості жестів (свайп для відкриття Drawer, жест "назад" на iOS).

### 5. Додаткові вимоги

- **Модульність**: Навігаційні стеки розділені на окремі файли в папці
  `src/navigation`.
- **Чистота коду**: Для назв екранів використовуються константи (`SCREENS` у
  `src/constants/screens.js`), що запобігає помилкам у назвах маршрутів.
- **Документація**: Код навігації містить коментарі, що пояснюють структуру
  вкладеності та логіку переходів.

## Завдання 3: Робота з API та Даними (Assignment 5)

Це завдання присвячене інтеграції зовнішніх API для отримання даних, їх обробці
та відображенню у застосунку.

### 1. Вибір та Налаштування API

- Для тестування отримання даних обрано публічний REST API —
  **JSONPlaceholder**.
- Використовуються ресурси `/posts` як замінники для нотаток щоденника.
- Створено файл `src/services/api.js`, де визначено константу `API_BASE_URL` для
  чистоти коду.

### 2. Інтеграція API

- Реалізовано асинхронну функцію `fetchLatestEntries` з використанням **Fetch
  API**.
- Логіка запитів винесена в окремий сервісний шар (`src/services/api.js`), що
  відповідає принципу модульності.
- Отримані дані інтегруються в Redux-сховище для подальшого використання у
  застосунку.

### 3. Відображення даних у списку

- На головному екрані (`HomeScreen.js`) реалізовано список останніх записів за
  допомогою компонента **`FlatList`**.
- Для кожного елемента списку використовується кастомний компонент **`Card`**,
  який відображає заголовок та превью тексту запису.
- Реалізовано `keyExtractor` для унікальної ідентифікації елементів списку.

### 4. Обробка станів завантаження та помилок

- **Loading**: Під час виконання запиту до API відображається індикатор
  завантаження **`ActivityIndicator`**.
- **Error Handling**: Реалізовано блок `try...catch` для перехоплення помилок
  мережі. У разі невдачі користувач бачить відповідне повідомлення та кнопку
  "Try Again" для повторного запиту.

### 5. Інтеграція з навігацією

- Елементи списку є інтерактивними: при натисканні на картку відбувається
  перехід до екрана деталей (`EntryDetailScreen`).
- Через параметри навігації передається унікальний ідентифікатор запису (`id`),
  що дозволяє екрану деталей відображати відповідну інформацію.

### 6. Додаткові вимоги

- **Модульність**: Чіткий розподіл між сервісами (API), компонентами та логікою
  екранів.
- **Документація**: Код містить коментарі JSDoc, що описують призначення функцій
  та структуру даних.
- **Чистота коду**: Використання сучасних хуків (`useEffect`, `useState`,
  `useCallback`) та дотримання стандартів іменування.

## Завдання 4: Керування станом (Assignment 6)

Це завдання присвячене інтеграції глобального керування станом у застосунок за
допомогою Context API та Redux Toolkit.

### 1. Аналіз та Проєктування

Для забезпечення цілісності даних та гнучкості інтерфейсу було визначено два
основні аспекти для глобального керування:

- **Тема (Context API)**: Глобальна палітра кольорів та режим (світлий/темний),
  що впливає на всі компоненти застосунку.
- **Нотатки щоденника (Redux)**: Централізоване сховище для списку записів, що
  потребує постійного доступу з різних екранів (Головна, Календар, Подробиці).

### 2. Реалізація Context API

- Створено **`ThemeContext`** та **`ThemeProvider`** у папці `src/context`.
- Провайдер надає доступ до поточного стану теми (`light`/`dark`), функцію
  `toggleTheme` для її зміни та об'єкт `colors` з палітрою кольорів.
- Застосовано кастомний хук `useTheme` у компонентах (`Button`, `Card`,
  `Typography`, `HomeScreen`) для динамічної зміни стилів залежно від теми.

### 3. Інтеграція Redux Toolkit

- Встановлено та налаштовано `@reduxjs/toolkit` та `react-redux`.
- Створено **`entriesSlice`** (`src/store/slices/entriesSlice.js`) з наступними
  операціями (reducers):
  - **`addEntry`**: Додавання нового запису на початок списку.
  - **`removeEntry`**: Видалення запису за його унікальним ідентифікатором.
  - **`updateEntry`**: Редагування існуючого запису.
- Налаштовано **`store`** та підключено його до застосунку через компонент
  `<Provider>` у файлі `App.js`.
- У компонентах використовуються хуки `useSelector` для отримання списку записів
  та `useDispatch` для виконання дій.

### 4. Додаткові вимоги

- **Модульність**: Контекст та Redux-слайси винесені в окремі директорії
  (`/context`, `/store`).
- **Чистота коду**: Використовуються константи для кольорів у контексті теми,
  код мемоізований для уникнення зайвих ре-рендерів.
- **Документація**: Файли містять JSDoc-коментарі, що пояснюють логіку роботи зі
  станом.

## Завдання 5: Оптимізація та Анімація (Assignment 7)

Це оновлення зосереджене на оптимізації продуктивності, зменшенні розміру бандла
та створенні плавних взаємодій з користувачем.

### 1. Анімації (Task 2)

- **Каскадна поява елементів списку**: Реалізовано за допомогою
  `react-native-reanimated`. Елементи записів на головному екрані тепер плавно
  з'являються та піднімаються вгору з каскадною затримкою, створюючи відчуття
  преміального продукту.
- **Мікро-взаємодії**: Кнопка "New Entry" та всі картки списків тепер мають
  тонку анімацію масштабування при натисканні (використовується `withSpring` у
  Reanimated), що покращує тактильний відгук.

### 2. Оптимізації (Task 3)

- **Мемоізація компонентів**: Основні компоненти інтерфейсу (`Card`, `Button`,
  `AppHeader`, `Typography`) обгорнуті в `React.memo`, щоб запобігти непотрібним
  ре-рендерам при зміні стану батьківських компонентів.
- **Стабільність посилань**: Обробники подій для навігації та діспатчу Redux у
  `HomeScreen` та `InsightsScreen` стабілізовані за допомогою хука
  `useCallback`.
- **Мемоізація даних**: Складні обчислення, такі як генерація календаря "Quick
  Jump" та форматування графіків, оптимізовані за допомогою `useMemo`.

### 3. Оптимізація бандла (Task 4)

- **Заміна залежностей**: Бібліотеку `axios` замінено на стандартний `fetch`
  API. Це дозволило зменшити розмір бандла, видаливши сторонню бібліотеку для
  мережевих запитів при збереженні повної функціональності.
- **Інструменти аналізу**: Встановлено `source-map-explorer` для моніторингу
  складу бандла та виявлення потенційних областей для подальшої оптимізації.

### Як запустити аналіз

Щоб побачити аналіз бандла:

1. Запустіть:
   `npx expo export:embed --platform ios --dev false --bundle-output dist/main.jsbundle --assets-dest dist --sourcemap-output dist/main.jsbundle.map`
2. Запустіть:
   `npx source-map-explorer dist/main.jsbundle dist/main.jsbundle.map`

## Фінальний проєкт: Комплексне вдосконалення застосунку (Final Project)

Цей розділ описує фінальний етап розробки застосунку MindLog, що включає
глибокий аналіз, розширення функціоналу, оптимізацію архітектури та
вдосконалення користувацького досвіду.

### 1. Аналіз та Стратегія розвитку

- **Поточний стан**: Застосунок має стабільну базу для ведення щоденника,
  включаючи авторизацію, створення записів та перегляд календаря.
- **Зони покращення**: Було визначено необхідність розширення аналітичних
  можливостей (екрани статистики), покращення навігаційної ієрархії для
  зручності використання та впровадження системи тем для персоналізації.

### 2. Розширення функціоналу та Компонентний підхід

- **Нові функції**: Додано інтеграцію з зовнішнім API для завантаження
  демонстраційних даних та розширено профіль користувача новими налаштуваннями.
- **Модульність**: Всі нові елементи інтерфейсу (кастомні поля вводу, модальні
  вікна, анімовані кнопки) винесені в окремі модулі в папці `src/components`, що
  забезпечує легкість їх повторного використання.

### 3. Керування станом та Оптимізація

- **Context API vs Redux**:
  - **Context API** успішно використовується для глобальної теми застосунку,
    оскільки ці дані змінюються рідко та впливають на весь UI.
  - **Redux Toolkit** обрано для керування масивом записів та налаштуваннями, що
    забезпечує високу продуктивність при великій кількості даних та складних
    операціях редагування.
- **Чистота коду**: Весь проєкт дотримується принципів DRY та SOLID, а складна
  логіка (наприклад, анімації та розрахунки статистики) детально прокоментована.

### 4. Вдосконалення UX/UI та Навігації

- **Інтерфейс**: Використано сучасні дизайн-патерни (glassmorphism, м'які тіні,
  гармонійні палітри), що робить застосунок естетично привабливим.
- **Навігаційна ієрархія**: Оптимізовано переходи між списком записів та
  деталями, додано підтримку жестів та плавні анімації переходу за допомогою
  `Native Stack Navigator`.

### 5. Документація та Результати

- Впроваджені зміни дозволили вивести MindLog на новий рівень якості,
  перетворивши його на повноцінний продукт, готовий до використання.
- Логіка прийнятих рішень базувалася на забезпеченні максимальної зручності для
  користувача та продуктивності застосунку на різних платформах (iOS/Android).
